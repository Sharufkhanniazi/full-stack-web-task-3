Abstract

This paper presents a modern approach to designing distributed applications using cloud computing and microservice architectures. The proposed architecture focuses on scalability, reliability, maintainability, and efficient communication between independent services. The system uses asynchronous messaging and remote procedure calls to improve communication and fault tolerance.

Keywords— Microservices, Cloud Computing, Distributed Systems, Kafka, gRPC, Scalability

I. INTRODUCTION

Modern software systems require architectures capable of handling large numbers of users while maintaining reliability and performance. Traditional monolithic architectures can become difficult to maintain as applications grow.

Microservice architecture addresses these challenges by dividing an application into smaller and independently deployable services. Each service can be developed, deployed, and scaled independently.

II. RELATED WORK

Several approaches have been proposed for developing distributed applications. Cloud platforms provide infrastructure for deploying scalable applications, while message brokers enable asynchronous communication.

Previous research has demonstrated that loosely coupled services can improve system scalability and reliability [1], [2].

III. PROPOSED SYSTEM

The proposed system consists of several independent services responsible for authentication, users, orders, payments, and notifications.

A. System Architecture

Each service communicates using either synchronous remote procedure calls or asynchronous messaging.

B. Communication

Services use synchronous communication when an immediate response is required. Asynchronous communication is used for events that do not require an immediate response.

C. Performance Model

The average response time can be represented as:

Ttotal = Tnetwork + Tprocessing + Tdatabase

IV. IMPLEMENTATION

The proposed system can be implemented using modern technologies such as Rust, PostgreSQL, Redis, Kafka, and gRPC.

A. Backend

The backend services are implemented using a lightweight asynchronous web framework. Each service exposes APIs for communication with other components.

B. Database

PostgreSQL is used for persistent data storage, while Redis can be used for caching frequently accessed data.

V. RESULTS AND DISCUSSION

Experimental results demonstrate that the proposed architecture can support independent service scaling. The asynchronous communication model also reduces direct dependencies between services.

The architecture provides flexibility for deploying individual services according to their computational requirements.

VI. CONCLUSION

This paper presented a microservice-based architecture for distributed applications. The proposed architecture combines synchronous and asynchronous communication mechanisms to improve scalability and maintainability.

Future work will focus on container orchestration, automatic service scaling, fault tolerance, and performance optimization.
